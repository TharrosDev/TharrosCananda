# Documentation

Each fact lives in one doc; the others link to it. Update a doc in the same PR as the change it describes.

| Doc | Covers | Read it when |
| --- | --- | --- |
| [`README.md`](../README.md) | Setup, checks, environment variables, repo layout, publishing a house report | You are starting out or running the checks |
| [`AGENTS.md`](../AGENTS.md) | Map of the code, gotchas, content-truth rules, workflow (`CLAUDE.md` imports it) | You are a coding agent, or a check failed unexpectedly |
| [`PRODUCT.md`](../PRODUCT.md) | Users, purpose, positioning, surfaces, services, evidence commitments | You are changing copy, pages or services |
| [`DESIGN.md`](../DESIGN.md) | Tokens, typography, layout, every page, components, motion | You are changing anything visible |
| [`OPERATIONS.md`](OPERATIONS.md) | Vercel, Supabase, Resend, DNS, intake and readership flows, runbooks, launch items | You are touching infrastructure or deploying |
| [`REPORT_REQUIREMENTS.md`](REPORT_REQUIREMENTS.md) | Adding a report the owner supplies as a PDF, and the checks it must pass | You are publishing a supplied report |
| [`DATA_SOURCES.md`](DATA_SOURCES.md) | Source register, evidence rules, rules for any future live data | You are adding sources, data or figures |
| [`SECURITY.md`](../SECURITY.md) | Reporting a vulnerability | You found a security issue |
| [`.impeccable/`](../.impeccable/) | Design direction contract and quality bar for design work | You are running a design pass |
